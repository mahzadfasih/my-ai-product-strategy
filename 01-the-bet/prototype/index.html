Under the hood

The rule derivation step parses normative statements out of the requirements text — modality (must / shall / should / must not), subject, attribute, operator and threshold — and compiles each into an executable predicate. The validation step resolves each rule's attribute against the project record's fields (fuzzy key match, unit normalisation across mm/cm/m) and evaluates it per record.

In this prototype that reasoning layer is a deterministic parser, not a model call — so the demo runs offline, with no key and no latency. The production path swaps extractRules() in engine.js for a single structured LLM call over the requirements document, which handles prose, tables and implicit cross-references that a regex cannot. The validation step stays deterministic on purpose: rules are auditable, and a PM can contest one.
